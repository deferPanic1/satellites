# Бэкенд: Cosmo Constellation Designer API

FastAPI-сервис, который считает всё, что рисует интерфейс. Контракт —
`docs/openapi.yaml`, типы фронта (`frontend/src/types/api.ts`) повторяют
его один в один.

## Запуск

```bash
uv sync                                   # из корня проекта
cd backend
uv run uvicorn src.main:app --port 8000 --reload
```

Фронт в dev-режиме проксирует `/api` на `127.0.0.1:8000` (см.
`frontend/vite.config.ts`), поэтому достаточно поднять оба процесса.

Всё вместе в контейнерах:

```bash
docker compose -f deploy/docker-compose.yml up --build
# интерфейс на http://localhost:8080
```

Папку со встроенными сценариями можно переопределить переменной
`COSMO_DATA_DIR` (в образе это `/app/data`, туда монтируется `case/Данные`).

## Ручки

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | живость и версия |
| `GET` | `/api/scenarios` | список встроенных сценариев с метаданными |
| `GET` | `/api/scenarios/{id}` | полный JSON сценария |
| `POST` | `/api/scenarios/upload` | загрузка файла (`multipart/form-data`) |
| `POST` | `/api/validate` | валидация без расчёта |
| `POST` | `/api/simulate` | полный расчёт на весь горизонт |

Некорректный сценарий — нормальный результат, а не сбой: **HTTP 200** и
`valid: false` со списком всех найденных ошибок. Коды 4xx оставлены за
ошибками протокола (нечитаемое тело, неизвестный режим маршрутизации,
файл больше 10 МБ).

## Устройство

| Модуль | Ответственность |
|---|---|
| `services/geometry.py` | **модуль организаторов + валидатор.** Позиции, видимость, рёбра сети. Не правим |
| `services/routing.py` | маршрут «клиент → шлюз»: BFS по переходам или Дейкстра по дальности |
| `services/simulation.py` | сборка полного ответа: метрики, причины перерывов, сводка |
| `services/validator.py` | приведение ошибок `geometry.validate` к формату спеки |
| `schemas/result.py` | схемы ответов |

Сервер не хранит состояние: сценарий приходит целиком в теле каждого
запроса. Один расчёт отдаёт всё сразу — 720 отсчётов за ~200 мс, ответ
920 КБ сырых и ~25 КБ под gzip, — после чего фронт крутит таймлайн локально
и к серверу не обращается.

Первая версия маршрутизации (`services/processing_graph.py`) и заготовка
серверной выгрузки (`api/export.py` со своими схемами) удалены: первая была
заменена на `routing.py`, вторая не импортировалась и падала с `TypeError`
на уровне модуля. Выгрузку строит фронт в `lib/resultExport.ts`.

## Проверка

```bash
uv run uvicorn src.main:app --port 8000      # в отдельном терминале
uv run python backend/tests/check_against_fixtures.py
```

Сверяет ответ `/simulate` с `frontend/tests/fixtures/simulate-*.json` — четырьмя
полными суточными расчётами независимой реализации. Сравниваются рёбра сети,
маршруты, причины перерывов, перерывы, метрики, константы и сводка.
