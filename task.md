# Контракт данных для модуля маршрутизации

Документ для разработчика, который пишет поиск маршрута.
Всё ниже проверено эмпирически на четырёх сценариях кейса × 720 шагов (2880 вызовов `snapshot`).

---

## 1. Что ты получаешь

Единственный источник данных — `geometry.snapshot(scenario, t_s)`.

```python
import geometry as G
scenario = G.load("01_full_constellation.json")   # dict, прошедший валидацию
snap = G.snapshot(scenario, t_s=3600)             # состояние сети в один момент
```

Вызов стоит **0.9 мс**. Полный суточный цикл (720 вызовов) — **0.65 с**.
Кешировать и оптимизировать не нужно.

Тебе нужны ровно две вещи: `snap` (динамика) и `scenario` (роли узлов, статика).

## 2. Структура `snapshot`

Четыре ключа:

```python
{
  "t_s": 3600,              # int, эхо аргумента
  "satellites": [...],      # список, длина = ВСЕГО аппаратов в сценарии
  "edges": [...],           # плоский список доступных контактов
  "elevation_deg": {...}    # словарь по наземным пунктам
}
```

### 2.1 `satellites`

```python
[
  {"id": "S01", "x_km": 6769.7595, "y_km": -1438.9568, "z_km": 0.0, "active": True},
  {"id": "S02", ...},
]
```

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `str` | Идентификатор из `scenario["design"]["satellites"][].id` |
| `x_km`,`y_km`,`z_km` | `float` | Координаты в системе, СВЯЗАННОЙ С ЗЕМЛЁЙ (уже повёрнутые на угол θ) |
| `active` | `bool` | `launch_batch <= launch_stage` И аппарат не в отказе на момент `t_s` |

**Здесь всегда ВСЕ аппараты сценария**, независимо от очереди запуска и отказов.
Неактивные отличаются только флагом; координаты у них считаются как обычно.

**Для маршрутизации этот список тебе не нужен.** Неактивные аппараты уже
исключены из `edges`. Список нужен только визуализации. Единственное применение —
если захочешь показать «маршрут шёл через S31, но он отказал».

### 2.2 `edges` — главное

Плоский список троек:

```python
[
  ["S01", "S02", 2700.4402373472476],    # ISL
  ["S01", "S16", 2700.4402373472460],    # ISL
  ["G_MUR", "S20", 1260.1933200301964],  # наземная линия
  ["C72", "S35", 1690.7468031879637],    # наземная линия
]
```

Формат элемента: `[id_1: str, id_2: str, distance_km: float]`

Это **все пары узлов, которые могут связаться в момент `t_s`**. Все проверки
(дальность ISL, непересечение Земли, порог угла возвышения, активность аппаратов,
недоступность шлюза) УЖЕ ПРИМЕНЕНЫ. Ребро в списке = связь разрешена, точка.

### 2.3 `elevation_deg`

```python
{
  "C72":   {"S01": -34.21, "S06": 16.54, "S35": 11.93, ...},   # ВСЕ активные
  "G_MUR": {...},
}
```

Первый уровень — все наземные пункты (клиенты И шлюзы).
Второй — **только активные** спутники.

**ВНИМАНИЕ: порог `min_elevation_deg` здесь НЕ применён.**
В словаре лежат и отрицательные углы (спутник под горизонтом, минимум −84.8°).
Для маршрутизации этот блок НЕ используй — бери связи из `edges`, там фильтр есть.
Нужен только для UI-панели («угол возвышения 17.2°»).

## 3. Инварианты — что можно предполагать

Проверено на 2880 снимках, нарушений ноль:

| Инвариант | Гарантия |
|---|---|
| Петель (`a == b`) нет | ✔ |
| Дубликатов рёбер нет | ✔ |
| Каждое ребро встречается РОВНО ОДИН РАЗ | ✔ (связь двусторонняя!) |
| Рёбер «земля ↔ земля» нет | ✔ никогда |
| В наземном ребре порядок всегда `[наземный_пункт, спутник]` | ✔ |
| `distance_km` всегда `float` и строго > 0 | ✔ |
| Неактивные аппараты в `edges` не встречаются | ✔ |
| `len(snapshot["satellites"])` == числу аппаратов в сценарии | ✔ |

Порядок рёбер в списке: сначала все ISL, затем наземные (по порядку `ground_sites`).
На этот порядок **не опирайся** — он деталь реализации.

## 4. Что предполагать НЕЛЬЗЯ

Жюри загрузит свой сценарий того же формата.

| Нельзя | Как правильно |
|---|---|
| Спутники называются `S01`, клиенты `C65` | Роли только из `scenario["ground_sites"][].role` |
| Один шлюз | Их может быть НЕСКОЛЬКО. BFS завершается на ЛЮБОМ |
| 48 спутников / 3 плоскости | `len(scenario["design"]["satellites"])` |
| 720 шагов | `horizon_s // step_s` |
| Тип ребра определяется префиксом ID | Сверяйся с множеством наземных ID |

Строй три множества один раз до цикла:

```python
SAT_IDS = {s["id"] for s in scenario["design"]["satellites"]}
GATEWAYS = {g["id"] for g in scenario["ground_sites"] if g["role"] == "gateway"}
CLIENTS = [g["id"] for g in scenario["ground_sites"] if g["role"] == "client"]
```

## 5. Из списка рёбер в граф

`edges` — перечисление пар, а не структура для обхода. Нужен список смежности:

```python
def build_adjacency(snapshot):
    adj = {}
    for a, b, dist in snapshot["edges"]:
        adj.setdefault(a, []).append(b)
        adj.setdefault(b, []).append(a)     # <-- ОБЯЗАТЕЛЬНО: ребро лежит один раз
    return adj
```

Если нужны расстояния (для Dijkstra):

```python
adj.setdefault(a, []).append((b, dist))
adj.setdefault(b, []).append((a, dist))
```

Узел без единого ребра в `adj` ОТСУТСТВУЕТ. Всегда `adj.get(node, ())`, не `adj[node]`.

## 6. Правила маршрутизации

Маршрут: `client -> спутник -> ... -> спутник -> gateway`

**Правило 1. Ретранслировать могут ТОЛЬКО спутники.**
Клиенты и шлюзы — терминальные узлы. Путь `C72 -> S12 -> C65 -> S02 -> G_MUR`
запрещён: он тащит трафик транзитом через чужой клиентский терминал.
Наивный BFS построит его с удовольствием.

**Правило 2. Любой шлюз годится.** Остановка на первом достигнутом.

**Правило 3. Старт — только выбранный клиент.** Для каждого клиента свой поиск.

**Правило 4. Каждый момент времени независим.** Никакого переноса состояния
между `t` — маршрут строится заново с нуля. Спутник за 120 с пролетает 911 км,
преемственности нет.

## 7. Референсная реализация

```python
from collections import deque

def find_route(snapshot, client_id, gateways, sat_ids):
    """Возвращает список ID от клиента до шлюза, либо None."""
    adj = {}
    for a, b, _ in snapshot["edges"]:
        adj.setdefault(a, []).append(b)
        adj.setdefault(b, []).append(a)

    prev = {client_id: None}
    queue = deque([client_id])
    while queue:
        node = queue.popleft()
        if node in gateways:
            path = []
            while node is not None:
                path.append(node)
                node = prev[node]
            return path[::-1]
        # ПРАВИЛО 1: разворачиваем только старт и спутники
        if node != client_id and node not in sat_ids:
            continue
        for nb in adj.get(node, ()):
            if nb not in prev:
                prev[nb] = node
                queue.append(nb)
    return None
```

BFS даёт минимум ПЕРЕХОДОВ. Для минимума километров — Dijkstra по `dist`.
Оба варианта стоит иметь: переключатель стратегий закрывает критерий
«обоснованность выбранного подхода» (15 баллов за алгоритмы).

## 8. Классификация причины отсутствия маршрута

Кейс требует показывать причину. Всё берётся из того же обхода:

| Код | Условие | Что показать |
|---|---|---|
| `no_sat` | `not adj.get(client)` | Над пунктом нет видимого спутника |
| `gw_down` | все шлюзы в `gateway_outages` на этот `t_s` | Шлюз выключен |
| `no_gw` | ни у одного шлюза нет рёбер | Шлюз не видит ни одного аппарата |
| `isl_break` | иначе | Спутниковая сеть разорвана |

Порядок проверок именно такой: от конкретного к общему.

```python
def classify(snapshot, scenario, client_id, adj, gateways, t_s):
    if not adj.get(client_id):
        return "no_sat"
    if all(any(o["gateway_id"] == g and o["start_s"] <= t_s < o["end_s"]
               for o in scenario["gateway_outages"]) for g in gateways):
        return "gw_down"
    if not any(adj.get(g) for g in gateways):
        return "no_gw"
    return "isl_break"
```

Улучшение для баллов за анализ устойчивости: при `isl_break` верни множество
узлов, достижимых из клиента (`set(prev)`). Тогда в UI можно написать не просто
«сеть разорвана», а «клиент достаёт до 12 аппаратов плоскости P3, но ни один
из них не связан с плоскостью P2, где находится шлюз».

## 10. Тестовые фикстуры

Конкретные точки для юнит-тестов. Проверено, воспроизводится.

### Маршрут есть

```python
# 01_full_constellation.json
t=0,    C72 -> ["C72","S35","S20","G_MUR"]   # 3 перехода, 5858 км
t=1800, C72 -> ["C72","S46","S31","G_MUR"]   # маршрут полностью сменился
t=3600, C72 -> ["C72","S42","S26","G_MUR"]
t=63600, C65 -> ["C65","S02","S03","S35","S36","G_MUR"]   # самый длинный, 5 переходов
```

### Каждая причина отказа

| Причина | Сценарий | Момент | Клиент |
|---|---|---|---|
| `no_sat` | 01_full_constellation | `t=55080` | C70 |
| `no_gw` | 01_full_constellation | `t=67200` | C65 |
| `isl_break` | 04_link_range | `t=2040` | C70 |
| `isl_break` | 03_satellite_outages | `t=23160` | C65 |
| `no_sat` | 02_first_launch | `t=0` | C65 |
| `gw_down` | **нет ни в одном сценарии** | — | — |

`gateway_outages` пуст во всех четырёх файлах. Ветку `gw_down` придётся
покрыть синтетическим тестом: возьми 01, добавь
`{"gateway_id": "G_MUR", "start_s": 0, "end_s": 3600}` и проверь,
что на `t=0` все клиенты получают `gw_down`, а на `t=3600` маршрут есть.

### Контрольные агрегаты за сутки

Если твой модуль даёт другие числа — ищи ошибку.

| Сценарий | C65 | C70 | C72 |
|---|---|---|---|
| 01 Полная | 96.67 % | 98.75 % | 98.89 % |
| 02 Первая очередь | 27.22 % | 15.83 % | 12.64 % |
| 03 Отказы | 79.31 % | 80.83 % | 82.50 % |
| 04 ISL 2000 км | 77.50 % | 62.22 % | 65.14 % |

(доля шагов, на которых существует маршрут; 720 шагов, step_s=120)

Максимальный перерыв, сценарий 01: C65 — 480 с, C70 — 120 с, C72 — 120 с.

### Тест на правило «клиент не ретранслятор»

Обязательный. Если его нет — правило рано или поздно сломают рефакторингом.

```python
def test_client_not_relay():
    scenario = G.load("01_full_constellation.json")
    for t in range(0, 86400, 120):
        snap = G.snapshot(scenario, t)
        for c in CLIENTS:
            path = find_route(snap, c, GATEWAYS, SAT_IDS)
            if path:
                # все промежуточные узлы — только спутники
                assert all(n in SAT_IDS for n in path[1:-1]), (t, c, path)
                assert path[0] == c
                assert path[-1] in GATEWAYS
```

## 11. Интерфейс твоего модуля

Чтобы стыковаться с остальной командой без сюрпризов:

```python
def route_all(scenario: dict) -> dict:
    """
    Возвращает:
    {
      "routes":  {client_id: [path | [] ...]},   # len == n_steps
      "reasons": {client_id: [None | str ...]},  # len == n_steps
    }
    """
```

Длина массивов строго `horizon_s // step_s`. Отсутствие маршрута — **пустой
список `[]`**, не `None`: этого требует формат выгрузки `cosmo-A-result-1.0`,
где запись должна быть для каждой пары «момент × клиент», включая пустые.

Метрики (доступность, перерывы, гистограмма переходов) — отдельный модуль,
он потребляет твой выход. Не смешивай.
