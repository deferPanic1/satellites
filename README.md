# Проектирование устойчивой спутниковой группировки

Интерфейс для проектирования низкоорбитальной группировки и оценки её
устойчивости. Инженер собирает конфигурацию, сервис считает сутки работы
сети и показывает, где именно и почему пропадает связь. Конфигурации
сохраняются вариантами и сравниваются между собой.

Базовый набор кейса: 48 аппаратов в трёх плоскостях, сутки расчёта шагом
120 с — 720 отсчётов.

## Запуск

```bash
docker compose -f deploy/docker-compose.yml up --build
```

Интерфейс на <http://localhost:8080>. Порты меняются через `deploy/.env`
(скопировать из `deploy/.env.example`).

Локально, для разработки — нужны [uv](https://docs.astral.sh/uv/) и Node 22+:

```bash
uv sync
cd backend && uv run uvicorn src.main:app --port 8000 --reload   # терминал 1
cd frontend && npm ci && npm run dev                             # терминал 2
```

Интерфейс на <http://localhost:5173>, запросы `/api` проксируются на порт 8000.

**Если бэкенд не поднялся**, интерфейс не умрёт: он посчитает модель в
браузере и покажет плашку «локальный расчёт». Это запасной путь для
демонстрации, а не режим по умолчанию — **видна плашка, значит числа считает
браузер, а не сервер.**

## Как этим пользоваться

**1. Загрузить проект.** Выбрать сценарий из набора — список приходит с
сервера вместе с метаданными (очередь запуска, дальность ISL, число отказов),
поэтому варианты различимы до загрузки. Либо загрузить свой JSON; при ошибках
выводится весь их список с путями до полей, а не первая попавшаяся.

**2. Посмотреть.** Глобус с аппаратами, лучами до наземных пунктов и текущим
маршрутом. Внизу таймлайн: воспроизведение, шаг, скорость от ×1 до ×600.

**3. Прочитать показатели.** Вкладка «Показатели»: по каждому наземному пункту
доступность, видимость, дельта к прошлому расчёту и суточная полоса связи.
Наведение показывает причину перерыва («перерыв 16:36–16:38, 2 мин, нет
спутника»), клик по участку переводит таймлайн на этот момент.

**4. Изменить конфигурацию.** Левая панель: этап развёртывания, фазирование,
дальность ISL, порог возвышения, наземные пункты, периоды недоступности
аппаратов и шлюзов, стратегия маршрутизации.

Правка **не пересчитывает модель молча** — она копится в черновике, а сверху
появляется список изменений и кнопка «Пересчитать». Так каждый расчёт
осознанный, и его результат есть с чем сравнить.

**5. Сохранить вариант.** Конфигурация вместе с расчётом уходит на вкладку
«Варианты»: за вариантом закрепляется цвет, его можно переименовать и вернуть
его конфигурацию в работу.

**6. Сравнить.** Отметить два и более варианта, выбрать базу, нажать `C`.
Сводная таблица с подсветкой лучшего в столбце, полосы доступности на одной
суточной сетке, максимальные перерывы и дифф конфигураций.

**7. Выгрузить** результат в формате кейса `cosmo-A-result-1.0`. Выгруженный
файл загружается обратно без потерь.

Горячие клавиши: `[` и `]` сворачивают боковые панели, `C` открывает сравнение.

## Как считаются маршруты

Геометрию — положения аппаратов, видимость, рёбра сети — считает расчётный
модуль организаторов (`backend/src/services/geometry.py`), он не правился.
Ниже то, что построено поверх него.

Расчёт независим по отсчётам: сеть пересобирается на каждом шаге с нуля.

### Поиск маршрута

Маршрут идёт от клиента до **любого** шлюза. Ключевое ограничение:
**наземные пункты трафик не ретранслируют.** Промежуточными узлами могут быть
только аппараты, шлюз — только конечным. Без этого правила клиент дотянулся бы
до шлюза через другого клиента, и доступность оказалась бы завышенной.

| Стратегия | Алгоритм | Что минимизирует |
|---|---|---|
| `min_hops` | поиск в ширину от клиента | число переходов |
| `min_distance` | Дейкстра от клиента | суммарную дальность в км |

Обе останавливаются на первом извлечённом шлюзе и восстанавливают путь по
массиву предков.

Переключатель нужен, чтобы обосновать выбор: на полной группировке
`min_distance` даёт маршруты короче на 300–370 км при том же числе переходов
и той же доступности — выигрыш в задержке достаётся бесплатно.

### Причины перерывов

Если маршрута нет, причина определяется от частного к общему:

| Код | Когда |
|---|---|
| `no_sat` | над клиентом нет ни одного видимого активного аппарата |
| `gw_down` | все шлюзы выключены |
| `no_gw` | ни один шлюз не видит ни одного аппарата |
| `isl_break` | спутниковая сеть разорвана между клиентом и шлюзом |

Соседние отсчёты без маршрута склеиваются в перерывы. Перерыв, упирающийся в
начало или конец суток, помечается `at_boundary`: его длительность занижена
границей расчёта, и считать её наравне с остальными нельзя.

### Метрики

По клиенту: доля отсчётов со сквозным маршрутом и доля отсчётов с видимым
аппаратом, достигнут ли целевой порог, самый долгий перерыв, суммарное время
без связи, список перерывов, статистика переходов с гистограммой и средняя
длина маршрута в километрах. По сценарию: достигнут ли порог всеми, худший
пункт, средняя плотность сети.

### Стоимость

Сутки, 720 отсчётов, 48 аппаратов — **около 200 мс**, ответ 920 КБ и ~25 КБ
под gzip. Поэтому расчёт запрашивается один раз целиком, а таймлайн дальше
крутится локально: во время воспроизведения сервер не дёргается.
